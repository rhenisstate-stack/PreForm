## Approved Snapshot Architecture

### 1. Storage Location & EF Core Mapping
The metadata snapshot is stored directly on `ExamAttempt`:
```csharp
[Column(TypeName = "jsonb")]
public string? MetadataSnapshot { get; set; }
```
- Mapped in `AppDbContext` via `entity.Property(ea => ea.MetadataSnapshot).HasColumnType("jsonb");`.
- Nullable to accommodate pre-existing legacy attempts without schema disruption.

### 2. Authority Boundaries
- **`ExamAttempt.MetadataSnapshot` (JSONB):** Authoritative for the frozen examination configuration as it existed when the candidate started the attempt.
- **`ExamAttemptQuestion` (Relational):** Authoritative for exact question membership, display ordering (`DisplayOrder`), and attempt response binding.
- **Strict Prohibition:** Candidate responses, question stems, option texts, answer keys, and grading outcomes are **never duplicated or stored inside the metadata snapshot**.

## Snapshot Lifecycle & Immutability Rules

1. **Atomic Creation:** Generated by the server inside `ExamAttemptsController.StartAttempt` during the attempt initialization transaction.
2. **Server-Authoritative:** Populated strictly from authoritative database entities (`Exam` and `Examination`). Client-supplied snapshot values are ignored and rejected.
3. **Application-Wide Immutability:** Once written, `MetadataSnapshot` is read-only. No endpoint, job, or administrative override modifies an existing snapshot.
4. **Legacy Fallback Specification:**
   - If `attempt.MetadataSnapshot == null`:
     - The read API queries the associated `Exam` revision record dynamically and constructs a transient snapshot view.
     - The response payload explicitly returns `"snapshotSource": "legacy_fallback"`.
     - **Documentation Invariant:** The system acknowledges that this fallback reflects the *current state* of that `Exam` record; it does not claim to reconstruct historical modifications if the legacy record was altered prior to P3.1 immutability enforcement.
     - Zero retroactive writes are performed to `MetadataSnapshot`. No fabricated data is inserted.
5. **Future Schema Version Handling:** If `schemaVersion > 1`, deserialization gracefully parses the known envelope properties and exposes raw payload without throwing deserialization exceptions.
