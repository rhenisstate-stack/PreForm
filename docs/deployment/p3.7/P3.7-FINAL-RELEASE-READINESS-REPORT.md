## 6. Security & Operational Readiness Summary

1. **Authentication:** Cryptographically signed session tokens (`prepford_session`) with server datastore revocation tracking.
2. **Mutual Gateway HMAC:** Canonical v1 request signing binding method, path with query string, timestamp, nonce, body hash, and caller claims.
3. **RBAC Boundaries:** Candidate access to administrative controllers is strictly rejected with `403 Forbidden`.
4. **Fail-Closed Protection:** Unconfigured `GATEWAY_SHARED_SECRET` aborts authentication immediately in Staging and Production.
5. **Observability:** Health probes distinguish liveness (`/api/v1/health/live`) from PostgreSQL database readiness (`/api/v1/health/ready`).

## 7. Outstanding Defects, Identified Risks & Mitigations

| Severity | Risk Description | Subsystem | Mitigation / Action Item |
|:---:|---|---|---|
| **LOW** | Process-local nonce replay cache | Security (`GatewayReplayProtection`) | Effective for single-instance staging. Deploy Redis-backed nonce cache prior to horizontal multi-replica scaling. |
| **LOW** | Body re-hashing defense-in-depth | Security (`PrepfordAuthHandler`) | Body hash is HMAC-bound (preventing tampering); recommend server-side stream re-hashing in future hardening. |
| **INFO** | Query parameter order sensitivity | Gateway HMAC | Signer and verifier enforce exact raw query string order (`Request.QueryString.Value`). Deterministic client query generation maintained. |
